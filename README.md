# Клинический компас

Система поддержки врачебных решений (СППВР) для врача-психиатра частной многопрофильной клиники.
Прототип для кейс-чемпионата «Клинический компас». Основной сценарий: повторный приём взрослого пациента с установленным ГТР. Дополнительно: первичная оценка пациентов, направленных терапевтом или неврологом, с безопасной маршрутизацией при критическом состоянии.

Врач получает данные пациента, диагностическую гипотезу, этап схемы лечения по КР Минздрава, проверку препарата **Авиандр®** (маритупирдин) и взаимодействий, а также предложения по маршрутизации. Все клинические решения подтверждает только врач.

> Учебный прототип. Все пациенты и данные синтетические. Клинические правила (`config/*.json`) — черновик по спецификации команды и требуют верификации по действующим клиническим рекомендациям Минздрава России.

> **Для команды:** блок вопросов о тревоге показывает отдельные ответы, без расчёта HADS-A и без её порогов. На положительном ответе на пункт 9 создаётся частичная запись и сигнал; врач видит уже введённые ответы. Телефон врача — заглушка, демо не является службой экстренной помощи.

## Запуск

**Windows (ноутбук для демо):** двойной клик по `start.bat` → http://localhost:3000; автозапуск при включении — `deploy/install-autostart.ps1`; подробности и доступ с телефона — `deploy/README.md`. Для ИИ-ассистента: `CLAUDE.md`. Контекст проекта (КЛК, паспорт v2, реестр CT01–CT20): `docs/context/`.

Нужен только Node.js 22.13+. У сервера нет внешних npm-зависимостей, `npm install` для запуска не требуется. Маскот — лёгкие картинки WebP/PNG, без 3D и внешних библиотек.

```bash
npm start          # http://localhost:3000   (PORT=3100 npm start — другой порт)
npm run dev        # тот же интерфейс с временной синтетической БД, без записи данных на диск
npm test           # автотесты: реестр КЛК T-01…T-25 и три сквозных случая, ядро правил, API
npm run backup     # резервная копия БД (VACUUM INTO)
npm run measure    # замеры доставки алерта и открытия карточки
PORT=3000 npm run loadtest -- 50 20   # нагрузочный тест: 50 параллельных × 20 запросов
```

На экране входа есть кнопки демо-входа. Логины: `doctor`, `maria`, `anna`, `igor`, `daria`, пароль у всех `demo` (только для демонстрации).

## Опросник СППВР (20 экранов, версия 2.0 по КЛК)

Источник логики: документ КЛК «Клинический компас | Медицинская часть» (`docs/klk/KLK_medical_part.pdf`, разбор и список изменений: `docs/klk/README.md`). Конфигурация: `config/sppvr.json`.

- **Блок A**: 9 пунктов PHQ-9, русская форма требует проверки. **Блок B**: отдельные вопросы о тревоге. Ответы сохраняются и отображаются врачу; сумма и пороги HADS-A не применяются. Если пункт PHQ-9 пропущен, его сумма не выводится.
- **Блок E**: проверка внимания и три повторных вопроса. ИКСО — экспериментальный технический индикатор (0–100), не валидирован; он не доказывает искренность и не меняет суммы шкал.
- Пункт 9 PHQ-9 > 0 — отдельный сигнал безопасности, независимо от суммы. Сразу открывается C7, частичные ответы отправляются серверу и формируется красный алерт. При потере связи экран C7 доступен, но отправка не подтверждается до восстановления связи.
- **Клинический блок C1–C12** (необязательный, четыре экрана, на любой вопрос можно ответить «не знаю»): длительность, функционирование, лекарства, побочные эффекты, мания, соматика, беременность, алкоголь, вещества, никотин, жалобы по органам. В суммы не входит. «Не знаю» хранится как неизвестное и никогда не превращается в «нет».
- Время заполнения: клиент считает активное время по каждому вопросу (скрытая вкладка не считается), сервер считает общее. Нетипичное время даёт пометку «нетипичное время: уточнить ответы», а не вывод о поведении пациента. Порог 4 минут из документа — только гипотеза.
- HADS-A: используются демо-вопросы и общие варианты ответов, а не проверенная форма. До подтверждения лицензии, формы и ключа нельзя представлять эту сумму как валидированный результат.

### Пациентский экран после опросника

На итоговом экране показана динамика PHQ-9: до пяти сохранённых заполнений, даты и суммы из серверного пересчёта исходных ответов; ответы на отдельные вопросы о тревоге доступны врачу; пропуски обозначены «нет суммы». Одна точка не изображается как динамика. При сигнале безопасности блок метрик не показывается; экран C7 и спокойная поза овечки сохранены. Кнопка «Зачем это нужно?» раскрывает нейтральное пояснение, а анимация отключается при `prefers-reduced-motion`. Исходные шкалы и клиническое применение требуют верификации.

Обычная отправка опросника использует уникальный токен: повтор при потере ответа сервера не создаёт вторую запись. До подтверждения отправки ответы сохраняются в sessionStorage этой вкладки; при закрытии вкладки до подтверждения они могут быть потеряны. Экран сообщает об отсутствии подтверждения и предлагает повторить.

### Сводка врача

Блок «Перед приёмом» показывает сопоставимые изменения ответов с датами, последнюю запись дневника и сообщения пациента после визита, а также отмеченные пробелы в лекарственных данных. Основания, недостающие данные и решение врача показаны рядом с рекомендацией. Если истории или сообщений нет, сводка прямо указывает это.

## Алерты трёх цветов

При новом красном сигнале открытый кабинет врача воспроизводит три коротких тона, если браузер разрешил звук. Кнопка «Включить звук сигналов» находится в верхней панели; при недоступности звука интерфейс показывает предупреждение. Звук зависит от браузера, устройства и открытого кабинета, а визуальный алерт остаётся доступным.

| Цвет | Условия | Действия системы |
|---|---|---|
| Красный | пункт 9 PHQ-9 > 0; ответ C7 «намерение/план/попытка»; психотические симптомы (отметка врача); SOS пациента; тяжёлая выраженность; тяжёлое НЯ | оповещение врача, экран безопасности пациента (112, телефон доверия), черновик маршрута, эскалация через 5 минут без реакции. **Ничего автоматически не блокируется** |
| Оранжевый | возможная мания (C5 «да»/«не уверен(а)»); ТТГ > 10 или тяжёлая аритмия; рост GAD-7 | пометка карточки, уточнение очно; Авиандр при этом показывается как «не рекомендуется автоматически» |
| Жёлтый | низкий ИКСО; неизвестные данные («не знаю»); 3 пропуска приёма подряд | пометка карточки, запрос на уточнение |

Статусы алерта по КЛК: создан, доставлен, открыт, принят, действие (с заметкой). Окно взаимодействий: зелёный, жёлтый, оранжевый, красный, серый. Зелёный показывается только при подтверждённых данных. ИМАО — красный, жёсткая блокировка; серотонинергические препараты (сертралин) — оранжевый; неизвестные данные — серый.

## Архитектура

```
public/          адаптивный клиент HTML/CSS/JS без сборки; маскот-овечка — `public/mascot/sheep.js`, `sheep.css`, спрайты в `sheep/`
server.js        HTTP API, сессии, SSE-оповещения, роли и права
src/engine.js    ядро: шкалы, подсчёт СППВР, проверка препарата и DDI, правила алертов и маршрутизации
src/protocol.js  протокол СППВР: гипотеза, этап схемы по КР, ситуация применения Авиандра, блокировки
src/service.js   сценарии: алерты, карточка врача, сводка изменений, решения врача и действия пациента
src/db.js        схема SQLite, демо-данные, пароли (scrypt), журнал аудита с цепочкой хэшей
config/          опросник, планы лечения, DDI, препарат, правила: данные, а не код
test/            автотесты
scripts/         backup, dev-preview, loadtest, measure
```

Журнал аудита защищён цепочкой хэшей (`GET /api/doctor/audit/verify`). Каждое решение врача хранит автора, время и версию справочников (КР, инструкция, правила).

## Ограничения и открытые вопросы для команды

- **Сертралин и Авиандр.** По КЛК зелёного статуса быть не должно; в прототипе оранжевый (серотонинергические средства, CYP2D6). Окончательный статус и формулировка за Ариной.
- **Показания.** По инструкции Авиандр показан при ГТР и тревожных состояниях после COVID-19 со стрессовой реакцией и нарушением адаптации. Аугментация при депрессивном эпизоде и острая стресс-реакция без COVID-19 вне инструкции, поэтому система помечает «вне инструкции», решение с обоснованием за врачом.
- **Взаимодействия CYP3A4** и снижение бензодиазепинов на 30–50% взяты из спецификации, в прочитанном тексте инструкции не найдены (`needs_verification`).
- **Позиционирование «вторая линия, препарат выбора при реактивных состояниях»** из спецификации в инструкции не найдено, источник нужно указать.
- **Лицензия HADS.** Утверждение «частичное использование юридически чисто» нужно подтвердить. PHQ-9 свободен для использования. Источник валидации русских версий нужно указать.
- **Пересчёт в «эквиваленты» удалён**: используется PHQ-9; для блока тревоги сумма HADS-A отключена до подключения соответствующей формы. В КЛК у теста T-03 вектор 2,3,3,3,2,3,2,3,2 даёт сумму 23, а не 22: нужно поправить документ.
- **Кабинета терапевта и невролога в прототипе нет**: источник направления отражён в карточке пациента, ветка «направление к психиатру» реализована как входящий пациент психиатра.
- Психотические симптомы, исключение БАР и соматические данные врач отмечает в блоке «Осмотр», автоматического получения из МИС нет.
- Экран безопасности: телефон доверия 8 (800) 100-49-94 взят из открытого перечня, актуальность и телефон приёмного отделения клиники нужно подтвердить.
- **152-ФЗ.** Для реального использования потребуются: хранение в РФ, шифрование, согласие на обработку, усиленная квалифицированная подпись врача. В прототипе только синтетические данные.
- Сессии в памяти процесса, для масштабирования нужен PostgreSQL и общее хранилище сессий.
- Прототип не является медицинским изделием и не предназначен для клинического применения.

## Овечка, геймификация и спокойный интерфейс


- **Овечка** — маскот пациентского интерфейса. `MASCOT(поза, класс)` в `public/app.js` вызывает `sheepHTML` из `public/mascot/sheep.js` и отдаёт `<picture>` с WebP (1x/2x) и PNG-запасом; позы wave / happy / cheer / care, спрайты и `index.json` — в `public/mascot/sheep/`, стили — `public/mascot/sheep.css`. Лёгкое покачивание на CSS; при `prefers-reduced-motion` анимации нет; поза care (экран помощи) всегда неподвижна.
- **Прежний Нейрончик v2.1** и эксперименты сохранены в `docs/mascot/` как архив. Прежний 3D-маскот «Облачко» (Three.js, GLB) удалён.
- **Геймификация** (`src/game.js`, `config/game.json`): искры за опросник (+50), шкалы (+30), дневник (+20), уровни и серия дней. Считается из сохранённых данных, штрафов нет, на экране безопасности баллов нет.
- **Мягкий алерт для пациента**: спокойная плашка со спокойной овечкой, обращением по имени и существующими контактами помощи; врач при этом получает красный алерт в полном объёме. Медицинские тексты, контакты и правила маршрутизации при подключении маскота не менялись.
- **Интерфейс в духе Flo**: у пациента на главном экране один главный шаг, остальное свёрнуто; экраны теста без шапки; у врача меню в шапке и только отклонения в сводке опросника.
